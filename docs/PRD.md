# PRD — Finance Control Mobile App

## 1. Мета продукту

Надати фізичній особі єдиний мобільний інструмент для:
- перегляду всіх банківських і брокерських рахунків в одному місці;
- планування очікуваних надходжень (зарплата, фріланс, дивіденди тощо);
- глибокої аналітики доходів і витрат у розрізі платформи, напрямку, місяця та року;
- прозорого обліку всіх комісій.

---

## 2. Цільова аудиторія

- Фізичні особи з рахунками одночасно в кількох банках і брокерів
- Трейдери/інвестори (IBKR)
- Люди, що отримують доходи з різних джерел і хочуть планувати cashflow

---

## 3. Екрани MVP

### 3.1 Dashboard
- Загальний баланс по всіх рахунках (з конвертацією у базову валюту)
- Картки-акаунти: Monobank, IBKR, PrivatBank, Zen
- Найближчі очікувані надходження (з Планера)
- Швидкий перехід до Аналітики

### 3.2 Транзакції
- Загальна стрічка всіх транзакцій у хронологічному порядку
- Фільтри: платформа, тип (дохід/витрата), дата, категорія
- Пошук по опису

### 3.3 Планер майбутніх надходжень *(новий модуль)*

#### Призначення
Дозволяє вручну занотовувати очікувані надходження на будь-який рахунок ще до того, як вони прийшли. Це дає змогу бачити прогнозований cashflow і порівнювати факт з планом.

#### Функції
| Функція | Деталі |
|---|---|
| Додати планове надходження | Сума, валюта, цільовий рахунок (Mono / PrivatBank / Zen / IBKR), дата очікування, назва/джерело, коментар |
| Статус надходження | `Очікується` → `Отримано` (автоматично або вручну) → `Прострочено` |
| Авто-зіставлення | Якщо до рахунку прийшла транзакція ≈ запланованій сумі (±5%) в ±3 дні — пропонується зв'язати |
| Повторювані надходження | Щомісячні / щотижневі / кастомний інтервал |
| Прогнозний cashflow | Графік балансу рахунку на 30/60/90 днів вперед з урахуванням планових надходжень |

#### User stories
- *Як користувач, я хочу додати очікувану зарплату 10 000 UAH на Monobank 25-го числа, щоб бачити, чи вистачить мені коштів до зарплати.*
- *Як користувач, я хочу бачити, яка частина моїх планових надходжень вже реалізувалася цього місяця.*

### 3.4 Аналітика *(новий модуль)*

#### Призначення
Повна статистика всіх фінансових подій з гнучкою фільтрацією та візуалізацією.

#### Режими перегляду
| Режим | Опис |
|---|---|
| По платформах | Доходи й витрати окремо для Monobank / IBKR / PrivatBank / Zen |
| По напрямку | Куди йдуть гроші (категорія витрат) / звідки приходять (джерело доходу) |
| По місяцях | Місячний cashflow: сума доходів, витрат, комісій, чистий результат |
| По роках | Річний cashflow з розбивкою по місяцях (waterfall або bar-chart) |
| Порівняння платформ | Пай-чарт або bar-chart: частка кожної платформи у загальних витратах/доходах |

#### Фільтри
- **Платформа:** Monobank, IBKR, PrivatBank, Zen (мультивибір)
- **Тип події:** Дохід / Витрата / Комісія / Переказ між рахунками
- **Напрямок:** звідки прийшли (MCC-код або ручна категорія) / куди пішли
- **Валюта:** UAH / USD / EUR / інша
- **Період:** довільний діапазон дат, або швидкі пресети: Цей місяць / Минулий місяць / Цей рік / Минулий рік / Весь час
- **Рахунок:** конкретна картка / депозит / брокерський субрахунок

#### Метрики (KPI-карти)
| Метрика | Формула |
|---|---|
| Загальний дохід за період | Σ транзакцій типу `income` |
| Загальні витрати за період | Σ транзакцій типу `expense` |
| Чистий результат | Дохід − Витрати − Комісії |
| Середньомісячний дохід | Дохід / кількість місяців у діапазоні |
| Сума комісій | Σ fee_amount |
| Найбільша витрата | max(amount) серед витрат |
| Найбільше надходження | max(amount) серед доходів |
| % виконання плану | Фактичні надходження / Планові × 100% |

#### User stories
- *Як користувач, я хочу побачити, скільки грошей я витратив у Monobank за квітень 2026 і скільки прийшло.*
- *Як користувач, я хочу порівняти витрати по всіх платформах за 2025 рік на одному графіку.*
- *Як користувач, я хочу відфільтрувати тільки надходження і побачити їх джерела (зарплата, фріланс, дивіденди).*
- *Як користувач, я хочу бачити, яка частка витрат припадає на IBKR-комісії відносно загальних витрат.*

### 3.5 Налаштування
- Підключення / відключення платформ
- Управління токенами (Monobank X-Token, IBKR Flex Token)
- Salt Edge OAuth consent для PrivatBank
- CSV-імпорт для Zen
- Базова валюта та курси конвертації
- Біометрична авторизація
- Темне/світле оформлення додатку
- Інструкція як отримати кожний токен/csv файл для аналітики

## 4. Нефункціональні вимоги

| Вимога | Значення |
|---|---|
| Безпека | Токени зберігаються у backend Vault, не у клієнті; HTTPS усюди; biometric lock |
| Продуктивність | Перший рендер Dashboard < 2 с (дані з SQLite кешу) |
| Офлайн | Повний перегляд кешованих даних без інтернету |
| Конфіденційність | Дані не передаються третім особам, EU GDPR-ready |
| Масштабованість | PostgreSQL + Supabase, горизонтальне масштабування backend |

## 5. MVP vs. Майбутні фічі

### MVP (v1.0)
- Інтеграції: Monobank, IBKR, PrivatBank (Salt Edge), Zen (CSV)
- Планер надходжень (ручне введення + авто-зіставлення)
- Аналітика (всі фільтри + місяць/рік статистика)
- Розрахунок і відображення комісій

### v2.0 (Майбутнє)
- ФОП-режим: PrivatBank AutoClient API і Monobank
- Zen Merchant Payments API
- Експорт у CSV/PDF
- Класифікація категорій транзакцій
